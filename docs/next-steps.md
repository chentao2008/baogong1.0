# 下一步开发清单

本项目已完成第一步：项目骨架和第一版开发约定。

后续建议按以下顺序推进。

## 1. 确认数据库模型

先基于 `docs/dev-agreement.md` 细化 PostgreSQL 数据表。

需要确认：

- 用户表字段
- 工序表字段
- 员工工序配置表字段
- 管理员员工权限表字段
- 报工记录表字段
- 月度工资汇总表字段
- 字段类型、索引和唯一约束

## 2. 维护前端 UI 规范文档

项目已建立 `docs/frontend-ui-guidelines.md`。

开发页面前必须阅读该文档。后续如果新增公共样式或基础组件，需要同步更新该文档。

该文档已约定：

- 公共布局
- 基础样式变量
- 登录布局
- 后台布局
- 员工端布局
- 按钮、输入框、表格、状态标签、弹窗等基础组件规范
- 手机端和电脑端适配规则

## 3. 维护 API 规范文档

项目已建立 `docs/api-guidelines.md`。

每次新增或复用接口后，都要更新该文档，记录：

- 接口路径
- 接口用途
- 使用页面
- 权限规则
- 请求参数
- 返回数据
- 关键业务规则

## 4. 搭建后端骨架

完成 FastAPI 基础结构：

- 应用入口
- 配置管理
- 数据库连接
- ORM 初始化
- 健康检查接口
- 基础目录划分

暂时不实现完整业务功能。

## 5. 实现登录和权限

先打通最核心的权限闭环：

- 统一登录
- 管理员和员工角色区分
- 登录后返回当前用户信息
- 后端接口权限保护

## 6. 实现后台管理

先实现管理基础数据：

- 工序新增、改名、改单价、停用
- 员工账号新增、停用
- 员工可报工工序配置
- 管理员可管理员工范围配置

## 7. 实现员工报工

完成员工端核心闭环：

- 获取当前员工可报工工序
- 选择日期和工序
- 填写数量
- 保存报工记录
- 保存当时单价
- 自动计算小计金额和当月汇总
- 当天正常提交直接生效
- 禁止未来日期提前报工
- 已有报工记录的日期不能再次提交或修改
- 管理员确认状态不影响工资计算

## 8. 实现查询统计

完成：

- 员工查询自己的历史数据
- 管理员查询权限范围内员工数据
- 按员工、日期、月份、工序统计

## 9. 测试和试运行

重点测试：

- 工资计算是否正确
- 改单价后历史工资是否不变
- 员工是否无法查看别人数据
- 管理员是否无法越权查看员工
- 停用工序和员工后历史数据是否仍可查
- 管理员确认状态是否只影响展示状态、不影响工资
- 未来日期是否无法报工
- 已有报工记录是否无法再次提交、覆盖或修改
