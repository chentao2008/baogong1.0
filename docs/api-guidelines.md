# API 规范文档

本文档记录后端 API 的设计约定、已有接口和后续接口登记规则。

后续按页面开发时，必须先阅读本文档，检查是否已有可复用接口。已有能力必须复用，不要重复创建功能相同的 API。

## 基础约定

- API 统一由后端 FastAPI 提供。
- 前端只通过 API 访问数据，不直接访问数据库。
- 后端负责权限校验、数据校验、工资计算和数据库写入。
- 前端负责页面展示、用户交互和调用 API。
- 业务接口建议统一放在 `/api` 前缀下。
- 健康检查接口可以不放在 `/api` 前缀下。

## 权限约定

所有业务接口都必须在后端做权限校验。

- 未登录用户不能访问业务接口。
- 员工只能访问自己的数据。
- 管理员只能访问被分配给自己的员工数据。
- 前端隐藏按钮或页面不等于权限控制，后端必须再次校验。

## 响应约定

第一版可以保持简单，但同类接口返回结构应保持一致。

建议成功响应：

```json
{
  "data": {},
  "message": "ok"
}
```

建议列表响应：

```json
{
  "data": [],
  "total": 0,
  "message": "ok"
}
```

建议错误响应：

```json
{
  "detail": "错误原因"
}
```

FastAPI 默认错误结构可以接受，但同一类业务错误应尽量保持一致。

## 接口命名约定

接口命名应围绕业务资源，而不是围绕某个页面。

例如：

- 推荐：`GET /api/me`
- 推荐：`GET /api/admin/employees`
- 不推荐：`GET /api/backend-query-page-user-list`

这样后台管理页面和后台查询页面需要员工列表时，可以复用同一个接口。

## 已有接口

### `GET /health`

用途：检查后端服务是否启动。

使用页面：无，开发和部署检查使用。

权限：不需要登录。

返回示例：

```json
{
  "status": "ok",
  "app": "employee-work-report"
}
```

### `GET /health/db`

用途：检查后端是否可以连接 PostgreSQL。

使用页面：无，开发和部署检查使用。

权限：不需要登录。

返回示例：

```json
{
  "status": "ok",
  "database": 1
}
```

## 待设计接口分组

后续第一版业务接口建议按以下分组设计。

### 认证与当前用户

- 登录
- 退出登录
- 获取当前登录用户

### 管理员后台管理

- 工序列表
- 新增工序
- 修改工序名称
- 修改工序当前单价
- 停用工序
- 删除工序或移出可选工序范围。删除只影响后续配置，不能影响历史报工记录中的工序名、当时单价和小计金额。
- 员工账号列表
- 新增员工账号
- 修改员工名称
- 修改员工明文初始密码或重置密码
- 停用员工账号
- 配置员工可报工工序
- 管理员账号列表
- 新增管理员账号
- 停用管理员账号
- 配置管理员可管理员工范围

权限要求：

- 最高权限管理员可以查看和维护全局员工、管理员和工序配置。
- 普通管理员只能查看和维护被分配给自己的员工账号。
- 普通管理员可以新增员工账号；新增后默认纳入自己的管理范围。
- 员工账号不能物理删除，只能停用。
- 前端页面隐藏不等于权限控制，以上规则必须在后端接口中再次校验。

当前前端账号管理页和工序管理页已先按以下接口形态实现演示交互，后续接后端时优先按这里落地，不要另起一套页面专用接口。

### `GET /api/admin/accounts`

用途：获取当前管理员可见的账号列表。

使用页面：后台账号管理页。

是否复用已有能力：新增。

权限：超级权限可查看全部账号；普通管理员只能查看自己和自己管理的员工账号。

请求参数：无。

返回数据：账号 ID、账号名称、权限类型、启用状态、管理人。

关键业务规则：员工账号只能看到其管理归属；账号停用后不能登录；前端隐藏账号不等于权限校验。

备注：前端临时使用浏览器会话演示数据。

### `POST /api/admin/accounts`

用途：新增账号。

使用页面：后台账号管理页。

是否复用已有能力：新增。

权限：超级权限可新增超级权限、管理员、员工账号；普通管理员只能新增员工账号，新增后默认纳入自己的管理范围。

请求参数：账号名称、密码、权限类型。

返回数据：新账号信息。

关键业务规则：账号名称不可重复；密码后续必须由后端安全保存，不能明文入库。

备注：当前页面先做前端演示校验，真实校验必须在后端完成。

### `DELETE /api/admin/accounts/{account_id}`

用途：删除账号。

使用页面：后台账号管理页。

是否复用已有能力：新增。

权限：仅超级权限可删除账号。

请求参数：账号 ID。

返回数据：删除结果。

关键业务规则：第一版原则上员工账号不物理删除，只做停用；如果保留超级权限删除入口，后端需要明确限制不影响历史报工归档。

备注：当前前端按用户需求保留超级权限删除演示动作，后端实现前建议再次确认是否改为“停用/隐藏”。

### `PATCH /api/admin/accounts/{account_id}/disable`

用途：停用账号。

使用页面：后台账号管理页。

是否复用已有能力：新增。

权限：超级权限可停用权限范围内账号；普通管理员只能停用自己管理的员工账号。

请求参数：账号 ID。

返回数据：更新后的账号状态。

关键业务规则：停用账号不能继续登录；历史报工和工资数据仍可查询。

备注：

### `GET /api/admin/processes`

用途：获取工序列表。

使用页面：后台工序管理页、员工报工页面工序选择。

是否复用已有能力：新增。

权限：管理员可查看全部工序；员工只能通过员工报工接口获取自己可报工的启用工序。

请求参数：可选状态筛选。

返回数据：工序 ID、工序名称、当前单价、启用状态。

关键业务规则：停用工序仍要保留在后台列表和历史数据里。

备注：

### `POST /api/admin/processes`

用途：新增工序。

使用页面：后台工序管理页。

是否复用已有能力：新增。

权限：管理员。

请求参数：工序名称、当前单价。

返回数据：新工序信息。

关键业务规则：工序名称不可重复；单价不能小于 0。

备注：

### `PATCH /api/admin/processes/{process_id}`

用途：修改工序名称或当前单价。

使用页面：后台工序管理页。

是否复用已有能力：新增。

权限：管理员。

请求参数：工序名称、当前单价。

返回数据：更新后的工序信息。

关键业务规则：修改当前单价不影响历史报工记录和历史工资，报工记录必须保存当时单价。

备注：

### `PATCH /api/admin/processes/{process_id}/disable`

用途：停用工序。

使用页面：后台工序管理页。

是否复用已有能力：新增。

权限：管理员。

请求参数：工序 ID。

返回数据：更新后的工序状态。

关键业务规则：停用后员工不能继续选择该工序，历史数据仍可查询。

备注：

### 管理员查询统计

- 按员工查询报工记录
- 按日期范围查询报工记录
- 按月份查询工资汇总
- 按工序查询工作量
- 查询综合统计数据

### 员工报工

- 获取当前员工可报工工序
- 提交当天报工
- 提交补填报工申请
- 提交报工修改申请
- 获取当前员工当月工资汇总

### 员工查询

- 查询自己的历史报工记录
- 查询自己的月度工资汇总
- 查看报工确认状态

### 审批与确认

- 管理员确认报工记录
- 管理员审批补填申请
- 管理员审批修改申请
